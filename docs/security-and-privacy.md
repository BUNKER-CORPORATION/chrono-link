# Security, privacy, and threat model

## Assets

- Proprietary source, specifications, and model logic.
- Raw or derived biosignal-adjacent recordings and metadata.
- Model payloads capable of executing code when deserialized.
- Validation, timing, and prediction evidence that may reveal internal behavior.
- CI credentials, repository permissions, and dependency provenance.

## Trust boundaries

| Boundary | Trusted input | Untrusted or sensitive input |
| --- | --- | --- |
| Configuration | Reviewed local JSON/CLI/environment | Unknown keys, paths, malformed JSON |
| Acquisition | Resolved BrainFlow facts | Device samples, timestamps, counters, markers |
| Replay | Locally approved NPZ | Any external or modified recording |
| Model load | Approved provenance plus explicit trust | Every joblib payload by default |
| CI | Pinned first-party Actions and repository code | Dependency downloads, pull-request changes |
| Artifact sharing | Sanitized JSON/plots | Raw EEG, recordings, models, secrets |

## Threats and controls

| Threat | Primary controls | Residual risk |
| --- | --- | --- |
| Arbitrary code through model payload | Refuse without trust; verify manifest/contract/hashes before unpickle; self-test after load | A trusted malicious payload can still execute |
| Corrupt or adversarial recording | Pickle disabled; strict dtype/shape/JSON/finiteness/continuity validation | Resource-exhaustion attacks remain possible within host limits |
| Raw data leakage | Local-only processing; gitignore; non-raw routine metrics/errors; explicit raw callbacks | Operators can still copy files or register unsafe callbacks |
| Dependency substitution/drift | Exact hashes; bounded metadata; direct compatibility pin; clean package install | PyPI/account compromise and unreviewed lock updates remain supply-chain risks |
| Workflow action mutation | Full commit SHA pins; least-privilege token; no credential persistence | Compromise of a pinned upstream commit or runner remains possible |
| Silent configuration typo | Strict schemas and `CHRONO_` allowlist | Correctly spelled but wrong values still require review |
| Partial/cross-gap windows | Counter/timestamp validation and full causal-state reset | Hardware faults may evade available signals |
| Artifact overwrite/race | Exclusive creation and atomic publish where supported | Host/filesystem failures can still interrupt cleanup |

## Model artifacts

SHA-256 proves that bytes match the manifest; it does not prove who created the bytes or that they are
safe. `--trust-model` records an operator decision. It is not isolation, signature verification, or a
malware scanner. Models should be transported through an approved authenticated channel and retained
with their source commit, validation report, and dependency lock.

## Data handling

Treat all recordings as sensitive even when generated by a synthetic source, because identical
formats and paths may later contain human data. Use least-privilege directory access, approved local
or encrypted storage, defined retention, and secure deletion appropriate to the deployment.

Do not place recordings, models, serial identifiers, credentials, or personal information in Git,
issues, logs, screenshots, or public CI artifacts. Prefer deterministic synthetic reproducers.

## CI and dependency security

CI has read-only repository permission, does not persist checkout credentials, pins every external
Action by full commit SHA, installs dependencies by hash, and publishes only test/smoke/package
artifacts. Dependabot proposes dependency and Action updates; every proposal still requires lock
regeneration, tests, review, and supported-platform evidence.

The BrainFlow/setuptools pin is a compatibility and availability control: unconstrained resolution to
setuptools versions without `pkg_resources` breaks the synthetic-board runtime on both supported
platforms.

## Vulnerability response

Follow [SECURITY.md](../SECURITY.md). Preserve relevant commits, manifests, hashes, sanitized logs, and
timeline evidence. Do not publicly disclose a suspected exploit or attach sensitive artifacts before
triage establishes a safe channel.
